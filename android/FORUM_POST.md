## 这是什么

原项目（见下方「开源与致谢」）是一个跑在 Linux 上的 BLE 服务：电脑或 NAS 用蓝牙连接酷态科充电器，通过网页和 MQTT 把数据接到 Home Assistant。

问题是很多人手上根本没有 7×24 开机的 Linux 机器，为了看个充电功率还要专门摆一台。

这个安卓独立版把原项目的业务引擎（协议、状态机、认证、数据库、网页界面）**原样嵌进 App**，只把蓝牙传输换成安卓原生 GATT。于是：

- 不用电脑、不用 NAS、不用 Docker，一部手机就够了
- 首次配置用小米云扫码自动拿设备信息，不用手动抓 Token
- 全部离线可用（只有小米云扫码那一步需要联网）
- 数据存在 App 私有目录，网页只监听 `127.0.0.1`，不对局域网开放

## 主要功能

手机界面（手机版 UI，默认浅色主题，中英文可切换）：

- 连接状态与一键连接/断开
- 场景模式：AI 模式 / 数码生态 / 单口模式 / 均衡模式
- 端口控制：C1 / C2 / C3 / USB-A 独立开关
- 实时功率：当前总功率、各端口功率
- 功率曲线：实时 + 30 / 60 / 120 分钟 / 24 小时区间
- 功率占比、息屏时间、USB-A 小电流
- 充电记录：今日 / 昨日 / 本周 / 本月 / 全部，单次会话详情（电量 Wh、均功率、峰功率、均电压、均电流）
- 延时关闭（倒计时）

配置页：

- 设备 MAC、Token（24 位十六进制）、BLE Key
- 小米云扫码自动获取设备信息（不用自己找 Token）
- 界面语言（跟随系统 / 中文 / English）
- 历史保留天数、网页端口
- 充电会话记录开关（即时生效）
- **后台运行**开关（默认开启，见下）

安卓外壳：

- 前台服务：按 Home 回到桌面后连接和记录继续跑，通知栏实时显示状态
- 通知栏可一键「停止」；App 内可重试恢复。熄屏、后台长时间运行都走前台服务
- 开机自恢复：「后台运行」开启时，手机重启后会自动把服务拉起来，不用手动开 App
- 充电历史可导出 CSV（走系统文件保存对话框）

## 与电脑/NAS 版的差异

- 安卓版**不包含 MQTT 和巴法云**：手机直连场景下没有 Home Assistant 可接，界面上也一并去掉了相关入口（原引擎代码保留，配置里强制关闭）
- 数据库路径、监听地址由 App 接管，只监听 `127.0.0.1`，不存在局域网暴露风险
- 协议与业务逻辑来自原项目 v1.1.0，未做改写，只替换了蓝牙传输层

## 安装与首次使用

1. 安装 APK，允许「附近的设备/蓝牙」权限。
   - **Android 11 及以下**：还需要定位权限，并且要打开系统定位开关，否则搜不到 BLE 设备。
2. 允许通知权限（用于显示后台连接状态、停止服务）。
3. 打开 App，点左上角齿轮进配置页，二选一：
   - 用小米云扫码自动获取：点击获取二维码 → 用米家 App 扫码 → 自动回填 MAC / Token / BLE Key（需要联网）；
   - 或手动填 MAC 和 Token（Token 为 24 位十六进制），BLE Key 可选但建议一起填。
4. 保存配置，本地服务会自动重启，随后点「连接设备」即可。
5. 配置页的「后台运行」默认开启：离开 App 后继续保持蓝牙连接，手机重启后自动恢复；不想要后台常驻就关掉它，此时离开 App 会停止服务，回到 App 会自动重新拉起。

## 已知限制（先看这里再动手）

- **真机实测还不完整**：界面、HTTP 接口、安装运行已在安卓 15 模拟器和一台 vivo（Android 16）真机上验证过；但真机上还没有连接真实充电器，充电功率、协议显示、端口控制的真实效果需要你用自己的设备实测
- 协议解析针对酷态科 10 号 Ultra（AD1204U）开发，其它型号未验证
- 不同厂商的省电策略差异较大，想让后台长时间稳定，建议把 App 加入电池优化白名单
- 充电器固件差异也可能影响连接稳定性，遇到异常欢迎回帖反馈
